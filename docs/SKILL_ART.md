# M12 "Yetenek Yolları" — skill art manifest

Everything here is generated by committed scripts (`tools/blender/gen_skill_art.py`,
`tools/blender/gen_skill_effects.py`, run headless by `tools/blender/build_all.ps1`); nothing was
downloaded. Asset paths below are runtime paths under `assets/` (the client loads `<path>.png`, the
asset cache picks the compiled premultiplied `.vtex` next to it).

## 2. Skill bar and tree — `ui/skillbar/<name>.png`

Palette from `client/ui/Theme.h` (dark panel, gold `#C9A247` / `#D9AE4A`, bronze border `#7A6236`).

**Slot geometry**: every slot piece is 64², the icon window is the rounded rect (6, 6)–(58, 58),
radius 7 → draw the icon at `slot × 52/64`, centred (48 px icon → 59 px slot; 64 px icon → 79 px).
Layer order per slot: `slot_back` → icon → overlays (`slot_cooldown` sweep / `slot_nomana` /
`slot_locked`) → `slot_frame_<state>` → `key_badge` + digit → rank pips.

| Name | Size | Use |
|---|---|---|
| `slot_back` | 64² | recessed well under the icon |
| `slot_frame_normal`, `slot_frame_hover`, `slot_frame_pressed` | 64² | ring over the icon (transparent window); hover adds a warm glow into the icon edge; pressed is darker with an inner top shadow |
| `slot_empty` | 64² | complete empty slot (well + dim frame + faint diamond); draw alone |
| `slot_cooldown` | 64² | window-shaped dark veil (alpha 0.66). The client already draws a clockwise sweep in code (M9); either keep that and use this as the colour/shape reference, or draw this texture clipped to the remaining sector |
| `slot_nomana` | 64² | "not enough mana": window-shaped cold blue tint with a blue inner edge. Guidance: draw it over the icon and also multiply the icon by about (0.55, 0.6, 0.85) — never grey it out completely (grey means cooldown / dead) |
| `slot_ready_flash` | 64² | gold-white glow hugging the window; flash ~0.25 s (alpha 1 → 0) when a cooldown ends |
| `slot_locked` | 64² | window veil + padlock (skill not learned / level too low) |
| `lock_icon` | 32² | padlock alone (tree nodes, tooltips) |
| `key_badge` | 32² | dark plate with bronze rim for the key digit; draw at ~18–20 px over the slot's top-left corner, digit centred in Theme `text` colour |
| `rank_pip_on`, `rank_pip_off` | 16² | single rank diamond |
| `rank_pips_0` … `rank_pips_3` | 64×16 | three pips centred (52 px used), N lit; draw under the slot / tree node |
| `tree_v_lit/_unlit` | 16×32 | vertical connector; tiles vertically (stretch or repeat) |
| `tree_h_lit/_unlit` | 32×16 | horizontal connector; tiles horizontally |
| `tree_elbow_se/_sw/_ne/_nw` + `_lit/_unlit` | 16² | corners; the letters name the two edges joined (s = bottom, n = top, e = right, w = left) |
| `tree_tee_s_lit/_unlit` | 16² | left + right + down |
| `branch_<key>` | 256×64 | branch header plaque: medallion with emblem on the left (circle centre (32, 32), radius 30), name plate to its right — write the branch name from x ≈ 70 px, vertically centred, `textTitle` colour. Keys: `hucum`, `siper`, `pusu`, `zehir`, `koz`, `kiragi`, `sifa`, `yargi` |
| `skill_point_marker` | 32² | gold disc in the M11 unspent-points style (`FFE08A → C98A1E`, rim `5A3A08`) with a dark four-pointed star: "skill point available" (pulse it like the M11 marker) |
| `skill_point_marker_blank` | 32² | the same disc without the star, for a number drawn on it |

Connector lines run through the track centre (x or y = 8 px) and reach the edges flat, so pieces
butt together without seams. Lit = learned path (gold core, glow), unlit = not yet.

## 2b. Status icons — `ui/status/<name>.png` (64², read at 24 px)

Round-cornered plate: **gold rim = buff, red rim = debuff**; "up" buffs carry a small green arrow
bottom-right, `weakened` a red down arrow. Draw at 24 px (mip 1 → linear), 36 px at 150 % UI.

Buffs: `attack_up`, `defense_up`, `attack_speed_up`, `dodge_up`, `max_hp_up`, `heal_over_time`,
`shield`. Debuffs: `burn`, `poison`, `slow`, `stun`, `root`, `weakened`, `taunted`.

## 3. Effects — `effects/<name>.vmesh`

All static, single material, base colour + emissive gradient maps (`<name>.png`, `<name>_e.png`),
drawn with `WorldRenderer::addEffectMesh` (opaque, no shadow). **Tint caveat**: `addEffectMesh`'s
tint multiplies the base colour only; the emissive (most of what you see) is not tinted. Hence the
pre-coloured variants; `_neutral` variants are greyscale and become freely tintable if the renderer
also multiplies the emissive factor by the tint for effects (one-line change, client agent's call).
Engine axes: +Y up, +Z forward. "Origin" is the mesh origin.

**Client (M12, docs/CLIENT_RENDERING.md §13).** `addEffectMesh` now takes an opacity (< 1: drawn after
the opaque scene with premultiplied blending, depth tested, not written, far to near) and a
`tintEmissive` flag (the tint multiplies the emissive factor too), so `fog_cloud`, the bubbles, rings and
auras read as translucent and the `_neutral` meshes take any colour. The client's choices of meshes,
lifetimes and scales per skill are in `client/world/SkillsView.cpp` (`skillUseArt`, `effectAura`,
`tickArt`); rings and clouds are tilted to the terrain's slope at their centre.
